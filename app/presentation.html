Architecture

02한눈에 보는 구조

호스트 (내 PC)브라우저 · app/ 폴더
⇄-p 8080:8080
컨테이너python http.server

포트 매핑이 다리를 놓고, 마운트/볼륨이 데이터를 연결합니다.
지금 이 슬라이드도 이 컨테이너가 서빙 중!

Build

03Dockerfile — 단 6줄

FROM python:3.12-slim        # 경량 베이스
WORKDIR /usr/src/app          # 작업 디렉터리
COPY app /usr/src/app         # 웹 파일 복사
VOLUME ["/usr/src/app/data"]  # 영속 데이터 지점
EXPOSE 8080                    # 포트 명시
CMD ["python3","-m","http.server","8080"]

FROM → COPY → CMD 순서로 "재료 → 조립 → 실행"을 정의합니다.

Demo 1

04포트 매핑 접속

$ docker run -d -p 8080:8080 myfirstmission-web
$ curl -I http://localhost:8080
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.12

왜 필요한가? 컨테이너는 격리된 네트워크 안에 있어요.
-p 8080:8080으로 호스트 포트와 이어줘야 밖에서 볼 수 있습니다.

Demo 2

05Bind Mount — 실시간 반영

$ docker run -d -p 8081:8080 \
    -v "$PWD/app":/usr/src/app python:3.12-slim ...
# 호스트에서 index.html 수정 →
$ curl -s http://localhost:8081 | grep "My First Mission"
<h1>My First Mission</h1>

호스트 폴더를 컨테이너에 직접 연결 — 파일을 고치면 재빌드 없이 즉시 반영. 개발용에 최적.

Demo 3

06Volume — 데이터 영속성

$ docker volume create myfirstmission-data
$ docker run --rm -v myfirstmission-data:/data \
    busybox sh -c "echo volume-test > /data/volume.txt"
# 컨테이너 삭제(--rm) 후 다시 읽기
$ docker run --rm -v myfirstmission-data:/data busybox cat /data/volume.txt
volume-test  ✅ 데이터 유지됨

컨테이너를 지워도 Docker가 관리하는 저장소에 데이터가 남습니다. 운영 데이터용.

Concepts

07핵심 개념 정리

Bind vs Volume

Bind = 호스트 경로 직접 연결(개발·실시간). Volume = Docker가 관리(운영·영속).

포트 매핑

-p 호스트:컨테이너. 격리된 내부 서비스를 밖으로 노출하는 다리.

권한 755 / 644

r=4·w=2·x=1. 755=소유자 rwx, 그룹·기타 r-x. 644=rw- / r--.

Git vs GitHub

Git=로컬 버전관리 도구. GitHub=원격 협업·PR·이슈 플랫폼.
